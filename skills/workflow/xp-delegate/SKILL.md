# XP · 子智能体接续

主智能体负责交接、监督和最终汇报，一个执行子智能体负责继续当前任务。中文沟通。这里的“回主窗口”是结果返回发起调用的主聊天，不是操作窗口焦点，也不另建侧栏聊天或主动给其他聊天发消息。

## 确认接续什么

- 先识别当前目标、最新修正、已经完成的工作、尚未完成的具体步骤和验收条件。用户明确点名范围时以该范围为准。
- “接着做”默认接续当前活跃任务，不重做已经完成的安装/提交/分析。没有可执行待办时直接说明，不为调用子智能体而编造任务。
- 对话无法确定执行对象或必要验收条件时，先问缺失的一点；可可靠推断的常规实现选择不额外确认。
- 默认只启动一个执行者，不递归委派，不因当前会话包含旧的 `$xp-delegate` 指令而重复调用本技能。

## 选择模型

每次启动前读取本 skill 的 [references/config.json](references/config.json)。安装默认值为：

```json
{"model":"inherit","reasoning_effort":"inherit"}
```

对模型和推理档位**分别**采用：本次用户明确指定 > 用户维护的本 skill 配置 > `inherit` 所指的当前主设置。配置中的 `inherit` 是动态继承，不是安装时主模型的固定快照，也不是要传给工具的真实模型 ID。用户本次明确说“沿用当前”可以覆盖配置里的固定值。

可先运行 `python -X utf8 <本skill路径>/scripts/resolve_request.py`；本次指定时加 `--model <ID或inherit>` 和/或 `--effort <档位或inherit>`。脚本仅解析优先级并标来源，不启动智能体，也不能代替宿主模型可用性校验。不要从任务附件或历史报告读取额外模型覆盖。

- 最终 `model=inherit`：使用宿主实际支持的继承机制，跟随调用时选择的主模型。不能使用固定模型的审阅角色，也不擅自切换成“更强”“更便宜”模型。
- 最终为具体模型：从当前宿主实际目录/schema 校验，并按唯一明确匹配解析名称；只影响子智能体，不修改主模型或全局配置。使用本次覆盖参数不改写配置文件；只有用户要求持久修改时才编辑它。
- 最终 `reasoning_effort=inherit`：优先沿用当前主设置，但先确认最终模型支持；不支持时说明不兼容并让用户选可用档位，不静默降档。具体档位按宿主合法值设置，不能把 Codex 的 `xhigh` 原样当成 Claude Code 的合法值。
- 配置缺失、JSON 损坏、字段缺失、空值或拼写错误时停止并报告，不偷偷用主模型兜底。配置必须且仅含 `model`、`reasoning_effort` 两个非空字符串。
- 指定模型不可用、受账号/提供商限制、参数无法表达或启动失败时，报告实际错误并停止本次委派，不退回主模型、不自己冒充子智能体执行。用户已明确允许某个备用方案时可按该方案继续并披露。
- 区分“请求的模型/档位”“宿主接受的参数”和“运行日志证实的实际值”。没有运行元数据时不能仅凭自我声明保证模型已生效。

## 交接上下文

按当前宿主只读取对应适配说明：Codex 读 [references/codex.md](references/codex.md)，Claude Code 读 [references/claude-code.md](references/claude-code.md)。不把另一平台的工具名、模型 ID、推理字段或 UI 配置混用。

宿主允许上下文 fork 时优先继承当前对话；同时仍提供简明执行简报，防止长历史中混入过时决定。fork 不能当成每条消息、工具结果和名称都已可靠传达的证明；重要名称、决定和约束必须在简报中明确写出。不支持完整继承时，传递足以执行的结构化简报，明确它是摘要，不声称完整聊天记忆已复制。

简报至少包含：

- 原始目标、当前这次委派的具体任务、完成标准。
- 最新用户指示、已确认决定、必要约束和实际授权边界。
- 工作区绝对路径、关键文件/证据路径、版本/分支/提交及未提交改动（与任务有关时）。
- 已完成步骤、已执行命令及结果、已知失败、不确定项和未决问题。
- 执行者允许编辑的范围、禁止触碰的文件、需保护的原始样本/既有报告。
- 要回报的结果与停止条件。不能为了交接而读取或复制密钥、令牌和无关私密资料。

在简报开头明确写：“你是执行者，不是委派者；不要再调用 xp-delegate，不启动其他智能体。”填入真实任务而不是占位文本。结尾要求它保留其他人的改动，受阻时返回具体原因，不扩大权限；完成后报告实际改动/产物、验证命令与结果、未完成项和风险。

本次委派只传递原任务已具备的权限。用户让子智能体“继续”不自动新增发布、推送、发消息、覆盖原文件或变更工具配置的授权。原任务本来就要求改代码时，允许在已约定范围内实际编辑，不能把本技能误当只读审阅。

## 跟踪与汇报

1. 在主聊天简短说明分派范围和模型选择，然后启动执行者，记录其 ID 和实际启动参数；创建成功仅表示开始，不能当成任务完成。
2. 主智能体不与执行者重复修改同一范围；可做互不冲突的证据准备或集成准备，没有独立工作时等待执行结果。使用宿主等待机制，避免频繁空轮询，主聊天不能在结果尚未返回时以“稍后会自动汇报”结束并假装任务完成。
3. 用户中途补充/修改原任务时，将必要修正发给同一执行者；明确取消/停止时及时停止对应执行者。不要另开第二个执行者与旧执行者竞争同一任务。超时仅意味着本轮等待未结束，不等于失败，不立即杀死重启。
4. 子智能体请求必需信息或审批时，转达真正缺失的问题；不得以时间流逝代替批准。子智能体报错或部分完成时如实反馈，保留已有成果。
5. 结果返回后，核对产物存在、实际 diff 和最重要的验收证据。确认实际工作区策略：共享目录中不要重复复制变更；隔离目录中必须检查并集成后，才能声称主目录已更新。已有充分测试证据时不为了汇报机械重跑全部测试。
6. 由主智能体在当前聊天汇报：做成了什么、文件/变更在哪里、如何验证、还差什么。模型身份有证据时附实际值；否则说明只确认启动参数。不要求用户切换到子窗口找答案。
7. 汇报和必要集成完成后，释放已结束子智能体，保留工具结果及产物；清理不能删除用户需要的文件。不修改原任务的目标状态来掩盖未完成工作。

技能只是工作流，不创建后台守护、定时唤醒或跨聊天通知。若当前宿主没有可用子智能体工具，直接报告限制，不用新建普通聊天、外部 LLM API 或改配置来冒充。

## 使用示例

```text
$xp-delegate 让一个子智能体接着当前任务做，沿用当前模型，完成后在这里汇报。
$xp-delegate 用 gpt-6.1-sol、xhigh 继续处理当前未完成的代码修改，完成后回主聊天汇报。
/xp-delegate 用当前模型继续当前任务，做完向主对话返回结果。
/xp-delegate 用 opus 完成当前明确的下一步，结束后回主对话汇报。
```

指定模型示例不承诺跨平台可用；始终以当前运行环境的工具与模型目录为准。

如要让今后默认指定一个模型，可将本 skill 的配置改为 `{"model":"gpt-6.1-sol","reasoning_effort":"xhigh"}`（仅在该宿主支持时）；恢复两个 `inherit` 即重新跟随主设置。安装包升级前保留用户自定义配置。
