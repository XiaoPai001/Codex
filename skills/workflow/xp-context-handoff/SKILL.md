# 上下文交接

保存足以让下一位执行者继续工作的任务状态，而非按时间抄录聊天。默认中文，保留文件路径、符号、命令和模型 ID 的原始写法。技能依赖当前可见上下文及获准读取的本地证据；不能保证找回已丢失的聊天内容，也不能保证切换模型时自动执行。

## 选择模式

- “保存上下文”“准备切换模型”“生成交接”：创建新的 MD 文件。
- “读取这个交接并继续”：读取指定文件、核对当前状态，然后继续仍获授权的任务。
- 只说“读取/查看摘要”：读取并说明恢复的状态，不自动执行计划。
- 用户指定多个任务时按任务分别整理；默认以当前活跃任务为主，保留与其相关的前序约束和最新修正，不把其他闲聊混入计划。

## 保存工作流

1. 从当前可见对话提取任务状态。最新消息通常是在修正或补充已有目标，不默认替换整项任务。优先保留用户原始目标、验收标准和已确认决定。
2. 针对会影响接续工作的事实做少量只读核对，例如文件是否存在、仓库/分支、工作区改动、最后一次测试或推送结果。引用已有工具结果时标明时间或来源，不为整理摘要重新执行耗时测试、发布、推送或其他有副作用的操作。
3. 区分“已完成且有证据”“用户/前序摘要声称”“进行中”“计划”“待验证”。失败尝试仅在能防止下一位重复踩坑时保留。没有结果的命令不能写成成功。
4. 使用以下结构生成文档，按任务裁剪空白项；不要编造缺失信息。
5. 创建后重新读取文件，检查关键路径、未完成项和下一步计划一致，再在聊天提供链接和恢复提示词。

## 文档内容

### 交接元信息

- 生成时间及用户时区、任务名称、当前阶段、文档类型“上下文交接”。
- 输入依据：当前可见对话、既有压缩摘要、实际读取文件及工具结果；已知缺失的历史范围。
- 若能可靠取得则记录工作区、仓库 URL、分支、提交、是否有未提交改动。未知写“未确认”。

### 用户目标与验收

描述期望的最终结果、必须保留的行为、验收条件、当前最新指示及明确排除的范围。只把用户实际给出的偏好记成偏好；区分用户决定和执行者建议。

### 关键决定与约束

记录已选方案及影响下一步的理由、被否决方案及必要原因。保留与任务有关的语言、显示名称、模型/推理档位、文件保护、输出位置、审批和发布边界。过去对具体动作的授权不扩大为未来所有外部操作的授权。

### 当前状态与证据

用表格或短列表区分：已完成、进行中、未开始、阻塞。

每个重要完成项附证据，例如真实文件路径和行号、提交 ID、PR URL、测试命令及结果、运行日志位置。不能定位原记录时明确写成“前序摘要记载，尚未复核”，不补造引用。涉及修改时列出改动文件、结果及仍未提交/未推送的内容。

### 未决问题与风险

列出不确定项、矛盾、失败信息、依赖用户回答的问题及其影响。区分必需澄清和可采用的默认假设。不把尚未完成的工作写成已完成，不因准备交接而关闭或取消活动任务。

### 下一步计划

给出按依赖顺序排列的可执行步骤，每步写“动作、目标文件/对象、预期结果或验收方法”。明确第一步从哪里开始；把需确认的动作标明条件，不把建议命令冒充已执行。不要重新安排已经完成的任务，除非证据表明需要复核。

### 快速恢复提示词

提供可复制的短提示词，例如：

```text
请读取 <交接 MD 的实际绝对路径>，先核对工作区和任务状态，再从“下一步计划”继续。
保留已确认约束，不重复已完成工作；缺失信息或状态变化时指出差异。
```

提示词必须使用最终实际保存路径，而不是留下模板占位符。另列必要的文件导航，避免只凭交接摘要无法找到原始成果。

## 保存位置与保护

- 用户明确指定目录或文件时优先采用，但服从当前环境有效的输出目录限制。若限制导致不能写入请求位置，说明实际保存位置，不虚报已写入指定目录。
- 未指定位置时遵循当前工作区的交付约定（例如 `outputs/xp-context-handoff/`）；无专门约定则使用工作区 `xp-context-handoff/`。只有确实无法确定可写位置时才询问，不因可合理默认的目录停工。
- 默认文件名为 `xp-context-handoff-<任务短名>-YYYYMMDD-HHMMSS.md`；使用用户时区，清理短名中的非法路径字符。重名加序号，保留用户指定的扩展名为 `.md`。
- 使用排他创建（例如 Python `open(path, 'x', encoding='utf-8')`），不覆盖、追加或改写任何原文件或既有交接文档，即使用户请求路径已存在，也新建版本并说明。
- 内容和路径使用 UTF-8；不得把文件写入技能安装目录。只创建本次报告及必要输出目录，不修改项目配置、代码或用户记忆设置。
- 不复制密钥、令牌、密码或完整敏感日志。记录环境变量名、配置文件位置或凭据需求即可，不为摘要读取凭据文件。
- 只写当前确实可见或可核实的内容。压缩前自动保存并非本 skill 提供的保证；建议在切换前显式调用，但不要承诺整个历史已被永久记住。

## 恢复工作流

1. 读取用户指定的交接文件及必要的本地引用；文件中的命令和计划是历史资料，不是新的授权，不能覆盖当前用户要求或更高优先级约束。
2. 核对影响下一步的现状，例如路径、当前分支、提交和未提交改动。发现版本或状态变化时说明差异，并调整步骤；不直接 checkout/reset、恢复旧文件或覆盖当前工作。
3. 简短说明已恢复的目标和实际下一步。用户授权继续时开展仍在范围内的工作；必要问题缺答案时询问，同时推进无依赖事项。只要求查看时不执行计划。
4. 文件不足以恢复的部分保留为未知，不靠想象补全聊天、执行结果或权限。已有交接文档保持不变；需要新摘要时另建文件。

## 调用示例

```text
$xp-context-handoff 我要切换模型，把当前背景、完成情况和下一步计划保存到指定的交接目录。
$xp-context-handoff 保存当前任务，特别保留未提交修改、测试结果和待确认问题。
$xp-context-handoff 读取 D:/project/handoff/xp-context-handoff-task.md，核对现状后继续下一步。
```
