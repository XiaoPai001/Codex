# XP · 调试状态对比

采集有明确边界的观察，输出变化事实和待验证解释。中文显示；使用当前主模型。先读 [references/mcp-and-snapshot.md](references/mcp-and-snapshot.md) 获取实际接口和快照格式。

## 两种模式

- **离线对比**：输入用户指定的两份快照，直接用附带脚本验证并比较，不连接或操作正在运行的程序。
- **现场采集**：先用 `GetModuleList` 核对响应是否有连接/解析错误，再结合 `IsDebugging` 确认可用目标，用 `IsDebugActive` 判断是否正在执行；两者不是同一含义。状态查询的 false 可能掩盖底层连接失败，不能单凭它宣称“已连接但无目标”。无目标或连接失败时说明不能采集，可验证离线样本；不要自动 attach 或启动游戏。

默认每段不超过 1 MiB、累计不超过 16 MiB，每次 `MemoryRead` 建议最多 4 KiB，按页面边界分块。未给出范围时从用户指定对象或已知指针缩小范围，必要时只询问观察范围；不能为了找字段默认转储全进程。

## 现场采集

1. 为一次 before/after 观察生成同一个随机 `session_id`，确认目标文件、版本、进程身份（可取得时）和线程。用户手工操作或重新启动后核对身份；不把同一路径或模块名当成同一进程。
2. 暂停状态才能获得相对一致的快照。运行中读取须标为不一致并排除出可靠对比；仅请求观察时不自动暂停。若用户明确要求控制执行，可暂停并核对状态；否则说明需要暂停，由用户完成。
3. 获取模块/线程/寄存器和指定内存范围；保存原始工具响应及采集起止时间。记录内存基址、模块基址/RVA（适用时）、堆对象来源、长度和读取失败。不要把 `MemoryRead` 错误文本、空值或短读转成零字节。
4. 采集完成再读运行状态、线程及指令指针，状态/线程/IP 改变或身份无法保证时标记 `consistency="unverified"`。已确认同一暂停目标才标 `paused`。这只是采集一致性检查，不声称 OS 级原子快照。
5. 保存 before，等待用户完成已约定的一次操作，再采集 after。已有明确两阶段授权时继续执行该范围，否则保留 before 并提供 after 的采集方法，不等待一个尚未发生的操作却伪造 after。

不自动运行/步进、设断点、改寄存器/内存/页权限、加标签或结束调试。用户明确指定动态实验时仅执行必要步骤并记录原先状态；不要清理或删除用户原有断点。不能把一次变化直接命名为血量、金币或背包数量，需要重复单变量实验或代码读写证据。

## 离线脚本

在本 skill 目录中执行（将路径替换为实际文件）：

```text
python -X utf8 scripts/compare_snapshots.py validate before.json
python -X utf8 scripts/compare_snapshots.py diff before.json after.json --out-dir <工作区输出目录>
```

脚本仅使用标准库，输入为 `xp-debug-snapshot-v1`。强制核对会话、目标身份、位数和暂停一致性；已知 PID 不同则拒绝比较。线程变化或缺失单列警告。只比较同一 ID 且基址和长度均一致的范围；重定位、对象搬移、缺失或失败范围列为不可比较，不能当成未变化。不同会话不能为凑结果手工改 ID；用户确需跨会话比较时另设计有证据的对象对齐方法。

输出精确变化字节数、连续变化块、寄存器变化、不可比较范围及截断标记；不合并相邻未变化字节充当变化数量。只展示块预览时保留完整计数。差异缺失不等于游戏状态完全相同，未采集内存和其他线程不在结论范围。

报告用证据编号链接原快照、原始 MCP 响应、哈希和采集条件，表格区分“观察”“推测”“待验证”“冲突”，列出候选字段的下一步验证判据。

## 输出保护

遵循工作区输出目录约定，无约定则 `xp-re-output/debug-diff/`。采集创建全新目录，JSON 用 UTF-8 排他创建；脚本自动创建唯一子目录并用 `x` 模式写 JSON/MD。任何原快照、已有报告、内存和磁盘文件都不覆盖。输出中不要收集与本次范围无关的凭据或全进程数据。

## 示例

```text
$xp-debug-diff 对比指定两份快照，找出角色对象中变化的字节，不猜字段含义。
$xp-debug-diff 采集当前暂停目标在指定地址起 0x100 字节的 before 快照，不运行游戏。
```
