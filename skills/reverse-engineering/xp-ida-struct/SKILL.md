# XP · IDA 结构恢复

从真实访问证据恢复布局，输出可验证的结构候选。中文报告，保留原始符号名。由当前主模型执行，不固定模型或推理强度。

## 连接与目标

先读 [references/mcp-adapter.md](references/mcp-adapter.md)，使用实际暴露的 `mcp__hex_rays_ida` 接口；没有 `decompile` 独立 MCP 工具，实际工作经 `reference` 查询 API 后交给 `execute_python`。

用户指定函数、对象、模块或地址时按该范围；确认游戏版本、架构、样本身份及 VA/RVA/文件偏移/对象偏移。多库时必须明确 `instance_id`，不凭默认目标猜库。地址类型不明先核对模块基址，不盲目换算。

库已打开时仅查询。无库时，使用用户指定样本的独立副本建立新的分析库；无输入则问目标位置，不扫描或启动任意游戏。打开库可能触发自动分析，不能声称绝对无副作用；本 skill 不显式改动原库。禁止将正在使用的 IDB 及其伴随文件直接复制成“可靠备份”。

## 恢复过程

1. 记录样本路径、SHA-256（可用时）、IDA 版本/架构、基址、库实例及工具输出来源。阅读目标及必要调用方/被调用方、既有类型，不先批量枚举整个游戏。
2. 找到对象指针的来源和别名传播。区分同一基址的字段访问、子对象、数组索引、栈变量、全局变量和内联对象，尤其注意 `this` 调整、多重继承和优化后的别名。
3. 为每条访问保留证据编号 E01 等：函数 VA/RVA、指令地址、指令/操作数、访问宽度与读写方向、对象基准和相关伪代码。反编译的类型是线索，优先用真实指令核对宽度、符号扩展、浮点及步长。
4. 推导字段候选，分别标注“观察”（访问偏移和宽度）、“推测”（类型、语义、对象关系）、“待验证”或“冲突”。读取 4 字节只证明本次访问宽度，不自动证明它是 int、float、字段完整长度或“生命值”。
5. 交叉检查多个使用点、分配/构造/析构、索引计算及动态记录。偏移间隙保持未知；偏移重叠可能是联合、位域、别名或不同布局，不能强行合成一个结构。分配大小也不必等于对象完整大小。
6. 对冲突按版本、架构、调用路径和基准分别列出。动态验证必须经用户给定的观察范围，用现有调试 MCP 只读取；需要执行、暂停或断点时遵循动态任务授权，不因恢复类型而自动运行游戏。

## 输出

生成新的 Markdown，至少含目标身份、覆盖范围、证据索引及字段表：

| 对象/版本 | 对象相对偏移 | 观察宽度/读写 | 类型候选与依据 | 语义/关系候选 | 状态 | 证据 |
|---|---|---|---|---|---|---|

写出最小确认布局、互相排斥的备选布局、尚未知的字段和具体下一步判据。可另存 `.h` 草稿，但未确认项使用 `unknown_*`，明确是否伪代码；不为编译通过补造 packing、指针宽度、总大小或填充。

每个实质性结论就近引用证据编号；证据索引定位函数/指令和工具结果文件。动态记录还需时间、会话、线程和模块基址，不能把地址独自当身份。静态反编译与汇编来自同一来源，不伪称两次独立实验。

遵循工作区输出目录约定，无约定则 `xp-re-output/ida-struct/`。创建带时间和唯一后缀的新目录；报告、证据 JSON 和头文件以 UTF-8 排他创建（`open(..., 'x')`），不得覆盖原二进制、IDB、报告或头文件。先保留原始 MCP 响应再做派生总结，不编造缺失返回。

默认不创建/应用类型，不重命名、不注释、不修补、不保存原库。用户后续明确要求写回时，先形成可检查的类型及变更清单，只应用到明确指定的新副本；禁止自动覆盖已有类型/名字。读回验证后才报告写回成功。未知项保持候选，不把推测永久写成确定语义。

交付前重读文件并检查来源、版本、状态和未知项，报告实际验证范围。`reference` 成功、发现工具和静态格式校验都不等同于真实目标恢复成功。

## 示例

```text
$xp-ida-struct 分析当前 IDA 库中指定函数对角色对象的字段访问，先只输出字段证据表，不改 IDB。
$xp-ida-struct 比较两个版本的指定对象布局，保留冲突和未知字段，另存报告。
```
