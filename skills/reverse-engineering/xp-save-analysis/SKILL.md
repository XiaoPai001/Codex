# XP · 存档格式分析

对真实存档建立可验证的格式假设。默认中文，使用当前主模型。先明确样本目录、游戏版本/平台、每份样本的操作差异以及目标是理解格式还是生成解析器；没有样本时询问路径，不扫描整盘。

## 先离线，再按需联动

使用只读标准库脚本 [scripts/analyze_saves.py](scripts/analyze_saves.py) 取得样本哈希、长度、熵、头部线索、固定偏移差异和指定窗口的数值视图：

```text
python -X utf8 scripts/analyze_saves.py before.sav after.sav --out-dir <工作区输出目录>
python -X utf8 scripts/analyze_saves.py sample.sav --probe 0x10:4 --probe 0x20:8 --out-dir <工作区输出目录>
```

默认每文件最多 16 MiB、合计最多 64 MiB、最多 16 个样本，超限明确失败；可用 `--max-bytes` 在硬上限内调整。不会截断输入却声称全量分析，不自动解压或执行样本。

样本未完整读取、读取时变化或缺失时停止对应结论。高熵只能是压缩/加密等线索，不能证明算法；文件头签名只是候选，需完整解析或调用链验证。

## 分析过程

1. 记录样本路径、SHA-256、字节数、版本/平台和实际操作。用多个基线与一次仅改变一个已知变量的样本组；区分“同样操作重复保存”造成的时间戳、随机数、重排等噪声。
2. 比较魔数、版本、长度、计数、偏移表、字符串、记录步长、对齐和尾部。脚本的差异是相同文件偏移上的字节比较；长度变化/插入可能导致整体错位，必须另做有证据的结构对齐，不把后续全部差异都当新字段。
3. 候选字段保留位置和原始 hex，分别尝试有依据的大小端、整数/浮点、编码和缩放。脚本展示的整数/浮点是机械解释，不证明类型、字段边界或含义。变量和字节同步变化只是相关性，需重复控制变量、解析往返或读写代码验证。
4. 分别描述磁盘文件、容器、解压/解密缓冲区、序列化记录和内存对象，不混用偏移。想确认压缩时只对副本做有输出上限和超时的解码；解压成功仍不证明字段语义。校验和、签名/认证标签及加密分开列假设，记录覆盖范围、端序和排除字段；一次命中不等于通用算法。
5. 确需读写函数证据才读 [references/mcp-link.md](references/mcp-link.md)，通过现有 IDA/DHS 工具从文件路径/API 引用追踪解析和序列化。先查可用目标，不自动启动/attach 游戏，不为找算法改内存或修补校验。只有离线分析也能交付时，不强行调用 MCP。
6. 用户要求解析器时按已证实布局生成单独脚本：拒绝未知版本、不足长度、越界/溢出计数、过度分配和解压膨胀；未知区域保留原字节和证据，不静默补零或丢弃尾部。没有证据的功能写“未支持”，不虚报全版本兼容。
7. 仅在明确要求写回/格式验证时，对新副本做解析→重建→再解析；区分语义等价与逐字节相同，保留原文件 SHA-256 并核对不变。回环成功不等于游戏能加载，未做游戏实测时明确注明。没有证据的校验/加密层不要生成看似可用的写入器。

## 证据和交付

每个实质性结论用证据编号，索引包含样本哈希、版本、文件绝对路径与半开偏移范围 `[start,end)`、原始片段及操作来源；代码证据再附模块/函数 VA/RVA、工具实例或动态会话与线程。

字段表至少包含：层级/版本、偏移与长度、原始字节、候选解释、验证方法、状态（观察/推测/待验证/冲突）及来源。明确冲突和替代解释，不根据扩展名或文件命名确定格式。

交付新的 MD、机器可读 JSON、必要的解析脚本和未决清单。沿用当前工作区的输出约定；无约定时使用 `xp-re-output/save-analysis/`。工具自动创建全新子目录，所有文件排他创建；不修改原存档、不覆盖报告、不把样本当代码执行、不自动上传原样本或分析结果。生成的脚本同样不得使用原输入作为输出，也不能用 force 绕过保护。

## 示例

```text
$xp-save-analysis 对比这些同版本存档，金币只改变了一次；找候选偏移，保留其他解释，不改文件。
$xp-save-analysis 分析指定存档的长度和校验线索，必要时只读查看当前 IDA 中的解析函数。
```
